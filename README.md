# work-brain — a git-backed Obsidian workOS

A work-only second brain. Markdown notes in an Obsidian vault, versioned in git,
kept current by scheduled syncs (Linear, Slack, email), fast local ingest
(meeting transcripts, dictated brain-dumps), and a per-turn Claude Code hook.
`AGENTS.md` is the entry point for any agent reading or writing the vault;
`DASHBOARD.md` is the auto-maintained portfolio view.

> **Status:** P1 substrate implemented. CI secrets are not yet provisioned, so
> the scheduled workflows will fail on cron until they are — expected. The
> webhook/vault service is not yet deployed (P2).

## The idea in one picture

```
                 weekly (GitHub Actions cron)          per event / on demand
                 ─────────────────────────────         ──────────────────────────
  Linear  ─┐                                   00-inbox/transcripts ─┐
  Slack   ─┼─► sync_*.py ─► notes + digests    dictated dumps ───────┼─► ingest / router
  Email   ─┘                    │                                    │        │
                                ▼                                    ▼        ▼
                        ┌───────────────────  the vault  ───────────────────────┐
                        │ AGENTS.md  DASHBOARD.md  02-projects (digests)         │
                        │ 03-meetings  05-feedback  06-interactions              │
                        │ 00-inbox/actions.md  ← keyword hits, carry Slack msg id │
                        └───────────────────────┬────────────────────────────────┘
                                                │  every writer refreshes the
                                                ▼  digest + DASHBOARD.md
                     me in Obsidian (obsidian-git) · Claude Code on a clone · MCP (P2)
```

Everything is plain markdown, and retrieval is **structure-first**: `AGENTS.md`
tells agents where things live, strict frontmatter + wikilinks + stable slugs
make grep work, and maintained digests make the common question cheap.
Semantic-search plugins (Smart Connections, Copilot) are optional human
conveniences over the same files — nothing load-bearing, no vector DB to run.

## Vault layout

| Folder | Holds |
|---|---|
| `AGENTS.md` | how agents read/write the vault: layout, conventions, what they may edit. **The agent entry point.** |
| `DASHBOARD.md` | auto-maintained portfolio view: projects by status, open actions count, ideas queue. Regenerated by every sync — machine-owned, don't hand-edit. |
| `00-inbox/actions.md` | todo inbox; each item embeds its Slack `channel`+`ts` for the update loop |
| `00-inbox/transcripts/` | raw meeting transcripts land here; the push-triggered CI action drains it |
| `00-inbox/braindumps/` | optional landing spot for dictated dumps |
| `01-daily/` | daily notes (dumps default here) |
| `02-projects/<slug>/` | `_project.md` (frontmatter + the `## Current state` digest) + `tasks/` (Linear issues) + `done.md` |
| `03-meetings/` | cleaned, wiki-linked meeting notes (raw kept in `_raw/`) |
| `04-people/` | one note per colleague; interactions link here |
| `05-feedback/` | positive + negative feedback from Slack/email |
| `06-interactions/` | weekly Slack digests |
| `07-reference/` | durable docs / knowledge |
| `99-meta/` | `sync-state.json` (cursors + dedup), done-log |

## The digest invariant

Every project's `_project.md` carries a maintained `## Current state` section
(~500 tokens: status, recent decisions, open threads, links deeper). **Every
writer that touches a project refreshes that section and `DASHBOARD.md` in the
same commit** — the refresh lives in `lib/vault.py` so each writer inherits it.
Answering "where is project X?" is therefore one file read: no query-time LLM,
no latency. Summarization is paid once at write time, where writes are rare and
reads are frequent.

## What runs when

| Cadence | Runs | Mechanism |
|---|---|---|
| Weekly | `sync_linear.py`, `sync_slack.py`, `sync_email.py` | GitHub Actions cron (`.github/workflows/weekly-sync.yml`) |
| Per meeting | Fathom → `webhook/` receiver commits raw transcript → push triggers `ingest-transcripts.yml`, which runs `ingest_transcript.py` (clean, wiki-link, file actions, refresh digests) | webhook push → GitHub Action |
| On demand | `braindump_router.py` (`/braindump` in Claude Code), `close_actions.py` | local |
| End of every Claude Code turn | `session_capture.py` → one batched `git add -A → commit → pull --rebase → push` | `.claude/settings.json` **Stop** hook (SessionEnd as backstop) |
| Every ~10 min while Obsidian is open | obsidian-git auto commit-and-sync | Obsidian "Git" community plugin |

Transcripts are hands-off: Fathom posts to the receiver the moment a meeting is
processed, the receiver commits a normalized file, and the push-triggered Action
cleans it in CI. Swap Fathom for any provider by adding one adapter — see
`webhook/README.md`.

The heavy syncs and transcript ingest run in CI so they don't depend on your
laptop being awake. The Claude Code hook does exactly one thing — the batched
commit/push — so a turn ends fast; it does **not** run ingest or `close_actions.py`.

All automated writers `git pull --rebase` before pushing and retry once on a
rejected push, so CI, the receiver, your Obsidian session, and Claude Code can
all write to the same repo without stepping on each other.

## Setup

1. **Vault**: open this folder in Obsidian; point Templater at `templates/`.
   Smart Connections / Copilot are optional if you want semantic search as a
   human convenience.
2. **Git**: `git init && git add -A && git commit -m init`, push to a *private* repo.
3. **obsidian-git** (the human-side sync mechanism — see below).
4. **Config**: copy `config.example.yaml` to `config.yaml`, set your Slack
   handle in `search_queries`, tune keyword lists.
5. **Secrets**: copy `.env.example` to `.env` for local use; add the same
   values as GitHub Actions secrets for CI. `.env` is read by CI and by scripts
   in local shells; on Windows PowerShell, set the variables in your session
   (`$env:ANTHROPIC_API_KEY = "..."`) or use an env loader — there is no
   `source .env`. Tokens/scopes below.
6. **Claude Code**: merge `.claude/settings.example.json` into your
   `.claude/settings.json`. `/braindump <text>` routes a dictated dump.

### obsidian-git (human-side convergence)

Hand-edits converge on the repo automatically — manual push is a backstop, not
the mechanism:

1. Install the **Git** community plugin (obsidian-git) and enable it.
2. Enable **"Pull updates on startup"**.
3. Enable auto commit-and-sync on a **~10 minute** interval.
4. Enable **"Pull changes before push"**.

### The Claude Code hook

Both `Stop` (per turn) and `SessionEnd` (backstop) run the same command:

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "python scripts/session_capture.py", "timeout": 60 } ] }
    ],
    "SessionEnd": [
      { "hooks": [ { "type": "command", "command": "python scripts/session_capture.py", "timeout": 60 } ] }
    ]
  }
}
```

The path is relative on purpose: hooks run with the project directory as cwd,
so it works identically under cmd, PowerShell, and Git Bash on Windows. The
script makes one batched commit per turn (never per-file) and does
`pull --rebase` before pushing.

### Tokens & scopes

- **Linear** — Settings → API → personal key → `LINEAR_API_KEY`.
- **Slack** — user token (`xoxp-…`) with `search:read` (sync) and `reactions:write`
  (the close-the-loop reaction). `search.messages` needs a *user* token; a bot
  token won't work. Full-firehose ingestion would need Enterprise Grid Discovery
  (admin-only) — the search approach is the no-admin path.
- **Gmail** — OAuth desktop client + Gmail API; mint a refresh token once. Non-Gmail:
  replace `sync_email.py` with an IMAP version keeping the same output.
- **Anthropic** — `ANTHROPIC_API_KEY` for transcript cleaning, dump routing, and
  digest refresh.

## The action-inbox loop

When a sync sees an action-keyword message, it appends to `00-inbox/actions.md`:

```
- [ ] review the DPA draft  (from slack, 2026-07-04) <!-- src:slack channel=C0ABC ts=1720099999.001 permalink=https://… -->
```

Tick the box, then run `close_actions.py`: it reads the embedded id, adds ✅ to
the original Slack message, and moves the line to `99-meta/actions-done.md`.
That `channel`+`ts` pair *is* the update-loop handle you asked for.

## Extending

- New source → new `sync_*.py` using `lib/state` (dedup) + `lib/vault` (writing
  + digest refresh — every writer must leave `## Current state` and
  `DASHBOARD.md` current); add a step to the workflow.
- Different transcript tool → just export into `00-inbox/transcripts/`; the
  ingester is format-agnostic (`.txt .md .vtt .srt .json`).
- Prefer local-only (no CI) → run the same scripts on a scheduler (Task
  Scheduler on Windows, `cron` elsewhere); nothing is GitHub-specific except
  the workflow files.
